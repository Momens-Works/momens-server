# 0006. API path·버저닝 정책: `/api` prefix 단일화 + 전 엔드포인트 버저닝

- 상태: Accepted
- 날짜: 2026-06-30
- 작성자: Kimgyuilli

## 맥락

`momens-server`는 레거시 Go `momens-api`를 점진적으로 대체하는 중이다. API path와 버저닝 정책을
처음 세울 때(MOM-23·25·26)는 컷오버 충격을 줄이는 쪽에 무게를 뒀다. 그래서 레거시에서 이관하는
엔드포인트는 기존 path를 alias로 함께 열어 두고(`/api/me`와 `/me`를 동시에 제공), 버저닝도 신규
API에만 적용하고 레거시는 면제했다. 이 절충은 ADR 없이 `docs/spec/api-versioning.md`에만 적혀 있었다.

그런데 막상 운영해 보니 이 이원화가 생각보다 비쌌다. path가 둘이면 ingress 분기 rule, Swagger 문서,
컨트롤러 mapping, 테스트가 전부 두 갈래로 늘어났다. "신규는 버저닝하고 레거시는 면제한다"는 규칙
때문에 엔드포인트를 만들 때마다 어느 쪽인지 매번 판단해야 했다. 게다가 레거시 클라이언트는 어차피
새 서버로 호출을 옮기는 순간 코드를 고치게 되므로(Phase 0: 레거시가 새 서버에 맞춘다), 그때 path와
헤더를 함께 맞추면 alias를 남겨 둘 실익이 크지 않았다.

이 트레이드오프를 TL과 직접 논의했고, **단기 컷오버 편의보다 장기적으로 단순하고 일관된 계약이
낫다**는 데 뜻을 모아 path와 버저닝을 처음부터 하나로 통일하는 방향으로 최종 확정했다.

## 결정

**모든 HTTP JSON API를 `/api` prefix 단일 경로 + 전 엔드포인트 버저닝으로 통일**한다.

1. **path alias 폐기**: 모든 엔드포인트는 `/api` prefix 단일 경로만 제공한다. 레거시 path
   alias(`/me` 등)는 두지 않는다.
2. **버저닝 일괄 적용**: 레거시 이관 엔드포인트를 포함한 모든 핸들러가 Spring API versioning의
   `version` mapping을 가진다. 초기 버전은 `1`이다.
3. **버전 전달**: 클라이언트는 `API-Version` request 헤더로 버전을 전달한다. 마이그레이션 중
   레거시 클라이언트가 깨지지 않도록 서버는 헤더 누락 시 **기본값 `1`로 처리**한다
   (`ApiVersionConfig.setDefaultVersion("1")`). 계약상 모든 클라이언트는 `API-Version: 1`을 보낸다.
4. **응답 body는 별개**: 응답 body shape의 Legacy compatible/Standard 모드는 이 결정의 범위가
   아니며 [ADR 없음 / `api-response-error-codes.md`]의 정책을 그대로 유지한다. path·버저닝 단일화와
   응답 body 호환은 독립적으로 다룬다.

상시 규칙은 [API 버저닝](../spec/api-versioning.md)·[OpenAPI](../spec/openapi.md)에 반영했다.

## 대안

- **레거시 alias 유지 + 신규만 버저닝**(기존 정책): 컷오버 순간의 충격은 작지만 path·문서·테스트가
  영구히 이원화되고, 엔드포인트마다 버저닝 여부를 판단해야 한다. 레거시 클라이언트가 어차피 전환
  시점에 코드를 손대므로 alias의 실익이 작아 기각.
- **버전 헤더 필수화(`setVersionRequired(true)`)**: 계약을 가장 엄격히 강제하지만, 전환이 끝나기
  전 헤더 누락 요청이 즉시 깨진다. 마이그레이션 안전을 위해 기본값 `1` 방식을 택하고 필수화는
  보류. 전환 완료 후 필수화 전환은 별도로 결정한다.

## 결과

- ingress는 `/api/*` 한 rule로 새 서버에 분기한다(`/me` 분기 불필요). 레거시는 root 경로(`/auth/*`
  등)만 쓰므로 충돌이 없다.
- 모든 컨트롤러 mapping에 `version = "1"`을 둔다. 신규 기능은 처음부터 버저닝을 갖춰 추후 v2 분기가
  자연스럽다.
- 헤더 누락이 v1로 처리되므로 전환 중 레거시 클라이언트가 깨지지 않는다. 다만 "모든 클라이언트가
  헤더를 보낸다"는 계약은 기본값 fallback에 가려 런타임으로 강제되지 않는다 — 전환 완료 후
  `setVersionRequired(true)` 전환을 재검토한다.
- 기존 spec 문서에만 있던 path/버저닝 정책이 ADR로 승격되어, 방향이 한 번 뒤집힌 맥락이 시점
  기록으로 남는다.
