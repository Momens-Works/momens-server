# 0002. 비즈니스 로직 위치 — 엔티티/서비스 절충

- 상태: Accepted
- 날짜: 2026-06-23

## 맥락

초기 컨벤션은 "비즈니스 규칙은 Service에"(서비스 중심)였다. 베이스로 삼은 SOPT Coding
Guide는 "비즈니스 로직은 가능한 Entity 내부에"(rich domain)를 권한다. 둘은 결이 다르다.

## 결정

절충안을 택한다.

- 엔티티: 자기 상태·불변식 로직(자신을 어떻게 바꿀지).
- 서비스: 오케스트레이션·교차 엔티티 규칙·트랜잭션 경계.

## 대안

- 순수 서비스 중심(anemic 엔티티): 로직이 서비스에 몰림 → 엔티티 빈약, 응집도 저하.
- 순수 rich domain: 모든 로직을 엔티티에 → 교차 규칙·트랜잭션 표현이 어색.

## 결과

- 좋음: 응집도 높은 엔티티 + 명확한 서비스 경계.
- 감수: "상태 로직 vs 오케스트레이션" 경계 판단이 사람마다 다를 수 있음 → 리뷰로 정렬.
