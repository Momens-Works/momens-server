# prod 소유권 이전 대상 (MOM-0909)
#
# ADR-0019 가 prod 스키마 주도권을 서버로 옮기기로 정했다. 그 결정의 마지막 조각이 소유권이다 —
# `ALTER TABLE` 은 GRANT 체계 밖에 있어서 어떤 권한 조합으로도 얻을 수 없고, 소유자만 할 수 있다.
# `GRANT ALL PRIVILEGES` 로도 `must be owner of table` 이 난다(쌍둥이에서 확인).
#
# 여기 적힌 테이블은 **레거시가 만들었지만 서버가 마이그레이션 파일을 갖는** 것들이다. 판정 기준은
# 심기 목록 28건이 `CREATE TABLE` 하는 대상이고, 그중 prod 에 실물이 없는 둘을 뺐다.
#
#   task_checklist_items  심기 목록의 V20260707120000 이 만들지만 그 파일은 부분 충돌이라 심고,
#                         실물은 보정 마이그레이션이 만든다. 서버가 만드므로 자동으로 서버 소유다.
#   task_roles            prod 에 존재한 적이 없다(설계 2.8).
#
# 실행 집합 14건이 만드는 12개 테이블은 여기 없다. 서버가 직접 만들므로 생성 시점에 서버 소유가
# 된다.
#
# 제외한 것과 이유:
#
#   schema_migrations                     레거시 러너의 이력이다. 레거시가 쓰므로 절대 넘기지 않는다
#   decisions, sync_states                서버가 파일을 갖지 않는다
#   retrieval_documents, retrieval_events,
#   retrieval_cursors                     momens-retrieval 소유
#   oauth_clients, oauth_grants,
#   oauth_access_tokens, oauth_refresh_tokens,
#   oauth_authorization_codes,
#   oauth_interactions, oauth_placeholder 레거시 MCP OAuth(000019). 서버가 파일을 갖지 않는다
#
# **소유권을 넘기면 이전 소유자가 그 테이블의 권한을 잃는다.** postgres 를 grantee 로 하는 ACL
# 항목이 새 소유자로 옮겨가기 때문이다(다른 role 은 영향 없음). 그래서 생성물이 이전과
# `GRANT ... TO postgres` 재발급을 짝으로 묶고, 전체를 한 트랜잭션에 담는다. 레거시가 지금 실제
# 트래픽을 받으므로 재발급 누락은 곧 레거시 장애다.
#
